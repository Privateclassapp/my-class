# کلاس من

نسخه ۲.۱.۰

برنامه‌ای آفلاین‌محور برای معلم فارسی‌زبان: مدیریت شاگردان، کلاس‌ها، حضور و غیاب، ترم‌های ۱۰ جلسه‌ای، پرداخت‌ها، نمرات و یادداشت‌ها؛ همراه با حساب معلم، همگام‌سازی امن با یک بک‌اند اختصاصی Google Apps Script، پرونده شاگرد و بررسی رسید پرداخت.

در نسخه ۲ معماری تغییر کرده است: خبری از Google Sign-In، Google Picker، API key یا فایل `drive.js` در مرورگر نیست. یک بک‌اند Apps Script که خودِ صاحب برنامه آن را اجرا می‌کند، داده‌ها را در Drive حساب خودش نگه می‌دارد و همه ورودها با نام کاربری و رمز عبور انجام می‌شوند.

## تغییرات نسخه ۲

- ورود معلم و شاگرد با نام کاربری و رمز عبور؛ هر نام کاربری در کل بک‌اند یکتا است.
- نقش‌ها: مالک (owner)، معلم و شاگرد. مالک حساب معلم‌ها را می‌سازد، رمزشان را بازنشانی می‌کند و فعال/غیرفعال می‌کند.
- هر معلم برای هر شاگرد حداکثر یک حساب شاگرد می‌سازد. رمز اولیه ۱۲ نویسه‌ای است و فقط یک بار نمایش داده می‌شود.
- داده‌های معلم به‌صورت local-first در IndexedDB همان دستگاه می‌ماند و نسخه همگام‌شده روی بک‌اند ذخیره می‌شود.
- همگام‌سازی با شماره نسخه (revision) انجام می‌شود. اگر نسخه سرور عوض شده باشد، ارسال خودکار انجام نمی‌شود و باید آگاهانه «دریافت از سرور» یا «ارسال نسخه این دستگاه» را انتخاب کنید.
- شاگرد با حساب خودش وارد برنامه `student/` می‌شود، پرونده شخصی‌اش را می‌بیند و رسید پرداخت می‌فرستد. نوشتن شاگرد فقط از طریق بک‌اند انجام می‌شود.
- تصویر رسید فقط هنگام درخواست از بک‌اند دریافت می‌شود و داخل JSON همگام‌شده قرار نمی‌گیرد.
- داده‌های مرورگر نسخه قبلی یک بار و با تأیید شما به حساب جدید منتقل می‌شود. داده‌های قدیمی Google Drive مهاجرت داده نمی‌شوند.
- پنل مالک فقط فراداده حساب‌ها را نشان می‌دهد؛ به داده درسی یا مالی معلم‌ها دسترسی ندارد.
- اسکریپت پشتیبان‌گیری روزانه (`backend/Backup.gs`) با نگه‌داری نسخه‌های تاریخ‌دار اضافه شده است.
- نسخه ۲.۱ خروجی تکه‌ای، آینه پشتیبان روزانه، سرور Standby فقط‌خواندنی و تغییر مسیر خودکار خواندن هنگام قطعی سرور اصلی را اضافه می‌کند.
- نسخه برنامه، Service Worker و بک‌اند به `2.1.0` رسیده و `drive.js` حذف شده است.

## ویژگی‌ها

- طراحی موبایل‌اول با منوی پایین: خانه، شاگردان، حضور و غیاب، مالی، بیشتر.
- رابط کامل فارسی و انگلیسی، راست‌به‌چپ و چپ‌به‌راست، با فونت وزیرمتن.
- تاریخ شمسی برای نمایش و انتخاب تاریخ؛ ذخیره‌سازی داخلی با تاریخ میلادی استاندارد.
- اعداد فارسی و مبلغ به تومان.
- تم روشن، تیره و خودکار.
- قفل اختیاری برنامه با رمز ۴ تا ۶ رقمی، جدا از ورود حساب.
- شاگرد خصوصی، نیمه‌خصوصی و گروهی؛ امکان عضویت در چند کلاس و درس خصوصی هم‌زمان.
- کلاس با چند روز و ساعت در هفته.
- سه مدل شهریه: ترم ۱۰ جلسه‌ای، هر جلسه، ماهانه.
- تقسیم خودکار شهریه کلاس بین شاگردان فعال در تاریخ ثبت.
- ثبت حضور، تأخیر، غیبت، کنسلی حساب‌شده و کنسلی جبرانی.
- پرداخت‌ها، بدهی، بستانکاری و تسویه.
- نمرات با نمودار پیشرفت و یادداشت درس.
- یادداشت خصوصی یا قابل نمایش در پرونده شاگرد.
- بایگانی شاگرد و کلاس بدون پاک کردن سابقه.
- همگام‌سازی امن با حساب معلم روی بک‌اند اختصاصی؛ بدون Google OAuth در مرورگر.
- حساب شاگرد با نام کاربری و رمز، پرونده اختصاصی و ارسال رسید پرداخت.
- پنل مالک برای ساخت و مدیریت حساب معلم‌ها.
- پشتیبان JSON، بازیابی، خروجی CSV حضور و پرداخت.
- پشتیبان‌گیری روزانه سمت بک‌اند با نگه‌داری قابل تنظیم.
- خروجی تکه‌ای checksumدار و آینه روزانه در حساب Google دوم.
- سرور Standby فقط‌خواندنی با ارتقای دستی و تأیید checksum.
- تغییر مسیر خودکار خواندن‌ها هنگام قطعی سرور اصلی؛ نوشتن‌ها همیشه روی سرور اصلی.
- حذف کامل اطلاعات با تأیید دو مرحله‌ای.
- نصب روی اندروید و اجرای آفلاین با Service Worker.

## معماری

```text
مرورگر معلم (PWA)  ─┐
                    ├─ POST JSON (text/plain) ──> Apps Script Web App
مرورگر شاگرد (PWA) ─┘                                  │
                                                       ├─ Drive: users.json، sessions.json
                                                       ├─ Drive: teachers/<id>/data.json
                                                       ├─ Drive: teachers/<id>/receipts.json
                                                       ├─ Drive: students/<id>/portal.json
                                                       └─ Drive: students/<id>/receipts/...
```

- آدرس بک‌اند در `config.js` با مقدار `backendUrl` تنظیم می‌شود.
- درخواست‌ها JSON هستند و پاسخ‌ها یکی از دو شکل `{ ok:true, data }` یا `{ ok:false, error:{ code, message } }` دارند.
- داده معلم اول در IndexedDB ذخیره می‌شود و بعد به بک‌اند همگام می‌شود.
- IndexedDB به حساب معلم محدود است و داده نسخه قبلی فقط یک بار به حساب جدید منتقل می‌شود.
- شاگرد برای دیدن پرونده به بک‌اند نیاز دارد؛ آخرین پرونده برای مطالعه آفلاین کش می‌شود.
- شناسه‌ها همیشه از نشست گرفته می‌شوند، نه از بدنه درخواست.

## پیش‌نیازها

- یک حساب Google برای صاحب بک‌اند (مالک برنامه).
- دسترسی به Google Apps Script و Google Drive.
- یک میزبان استاتیک مثل GitHub Pages برای فایل‌های برنامه.
- Node 18 یا بالاتر فقط برای اجرای تست‌ها؛ اجرای برنامه به build یا npm نیاز ندارد.

## راه‌اندازی بک‌اند

راهنمای کامل در [`backend/README.md`](backend/README.md) است. خلاصه:

1. در <https://script.google.com> یک پروژه جدید بسازید و محتوای `backend/Code.gs`، `backend/Backup.gs` و `backend/Export.gs` را در سه فایل کد جای‌گذاری کنید.
2. فایل manifest را از `backend/appsscript.json` جای‌گذاری کنید و runtime را V8 بگذارید.
3. در Script Properties این مقادیر را تنظیم کنید:
   - `OWNER_USERNAME`: نام کاربری مالک (۳ تا ۳۲ نویسه؛ حروف کوچک انگلیسی، عدد، نقطه، خط تیره یا زیرخط).
   - `OWNER_SETUP_PASSWORD`: رمز اولیه مالک، حداقل ۱۰ کاراکتر.
   - `OWNER_DISPLAY_NAME`: اختیاری.
   - `EXPORT_SECRET`: اختیاری؛ برای خروجی کامل پشتیبان. اگر خالی باشد هنگام راه‌اندازی ساخته می‌شود.
   - `BACKUP_RETENTION`: اختیاری؛ تعداد نسخه‌های پشتیبان، پیش‌فرض ۱۴ و حداکثر ۶۰.
4. تابع `setupOwner` را یک بار اجرا و مجوزهای Drive را تأیید کنید. بعد از اجرا `OWNER_SETUP_PASSWORD` خودکار حذف می‌شود.
5. از منوی Deploy یک Web app بسازید:
   - Execute as: **Me**
   - Who has access: **Anyone**
6. آدرس `/exec` را کپی کنید. این آدرس در مرحله بعد در `config.js` قرار می‌گیرد.
7. برای فعال کردن پشتیبان روزانه، یک بار `backupCreateSnapshot` و بعد `backupInstallTrigger` را اجرا کنید. جزئیات بازیابی در `backend/README.md` آمده است.

## تنظیم برنامه معلم

فایل `config.js` فقط آدرس بک‌اند اصلی و (اختیاری) بک‌اند پشتیبان را دارد:

```js
(function (root) {
  'use strict';

  root.APP_CONFIG = {
    backendUrl: 'https://script.google.com/macros/s/XXXXXXXX/exec',
    fallbackUrl: ''
  };
})(typeof globalThis !== 'undefined' ? globalThis : this);
```

- آدرس‌ها را بدون `/` انتهایی بگذارید.
- `fallbackUrl` را فقط وقتی پر کنید که سرور آینه/Standby راه افتاده است.
- هیچ Client ID، API key، رمز یا قرارداد محرمانه‌ای در `config.js` قرار ندهید.
- اگر آدرس بک‌اند عوض شد، `config.js` و نسخه Service Worker را به‌روزرسانی کنید.

### تغییر مسیر خودکار

- بعد از دو خطای زیرساختی پیاپی (شبکه، timeout، خطای ۵xx/429 یا پاسخ HTML) در
  پنج دقیقه، برنامه تا پنج دقیقه فقط خواندن را از `fallbackUrl` انجام می‌دهد.
- خطاهای ورود، دسترسی و اعتبارسنجی باعث تغییر مسیر نمی‌شوند.
- همه نوشتن‌ها (همگام‌سازی، مدیریت حساب و ارسال رسید) همیشه به `backendUrl`
  می‌روند و هرگز روی Standby نوشته نمی‌شوند.
- نشست هر سرور جدا ذخیره می‌شود؛ ممکن است برای سرور پشتیبان یک بار دوباره
  وارد شوید.
- هنگام فعال بودن Standby، نوار «سرور پشتیبان — فقط خواندنی» و دکمه تلاش دوباره
  برای سرور اصلی نمایش داده می‌شود. فرم رسید شاگرد غیرفعال می‌شود.

## انتشار روی GitHub Pages

1. همه فایل‌های ریشه برنامه را در ریشه یک مخزن GitHub بگذارید؛ پوشه `student/` باید کنار `index.html` باشد.
2. فایل مخفی `.nojekyll` را در ریشه نگه دارید.
3. در **Settings > Pages** گزینه **Deploy from a branch**، شاخه `main` و پوشه `/(root)` را انتخاب کنید.
4. آدرس معمولاً `https://USERNAME.github.io/REPO/` است.
5. برنامه را در Chrome باز کنید و از منوی مرورگر نصب کنید. در iOS از Safari و **Add to Home Screen** استفاده کنید.
6. Service Worker و نصب PWA فقط روی `https://` یا `http://localhost` کار می‌کنند؛ `file://` مناسب نیست.

برای آزمایش محلی:

```bash
python3 -m http.server 8000
```

سپس `http://localhost:8000` را باز کنید.

## اولین ورود و ساخت حساب‌ها

1. برنامه را باز کنید. صفحه ورود معلم نمایش داده می‌شود.
2. با `OWNER_USERNAME` و رمزی که در `OWNER_SETUP_PASSWORD` گذاشته بودید وارد شوید.
3. اگر داده نسخه قبلی روی همان مرورگر وجود داشته باشد، یک بار پیشنهاد انتقال داده نمایش داده می‌شود. این کار فقط یک بار انجام می‌شود.
4. به **تنظیمات > مدیریت** بروید:
   - **مدیریت حساب شاگردان**: ساخت حساب برای شاگردان، ساخت رمز جدید، فعال/غیرفعال کردن و کپی متن ورود.
   - **مدیریت حساب معلم‌ها**: فقط برای مالک. ساخت حساب معلم، بازنشانی رمز و فعال/غیرفعال کردن.
5. برای ساخت حساب شاگرد:
   - اول داده‌های معلم را با بک‌اند همگام کنید. ساخت حساب برای شاگردی که در نسخه همگام‌شده سرور نیست، خطای «نیاز به همگام‌سازی» می‌دهد.
   - در صفحه شاگرد یا در **تنظیمات > حساب‌های شاگرد** دکمه **ساخت حساب** را بزنید.
   - نام کاربری پیشنهادی را بپذیرید یا عوض کنید. نام کاربری باید در کل بک‌اند یکتا باشد.
   - رمز ۱۲ نویسه‌ای فقط یک بار نمایش داده می‌شود. همان لحظه متن ورود را کپی و به شاگرد بدهید.
6. اگر رمز گم شد، از همان صفحه **رمز جدید** را بزنید. رمز قبلی و نشست‌های فعال آن حساب باطل می‌شوند.
7. برای قفل محلی دستگاه، در **تنظیمات > رمز و امنیت** یک رمز ۴ تا ۶ رقمی تعیین کنید. این رمز جای ورود حساب را نمی‌گیرد.

## شروع استفاده

1. از بخش **شاگردان** شاگرد اضافه کنید. نام الزامی است؛ تلفن، سطح و یادداشت اختیاری‌اند.
2. اگر شاگرد درس خصوصی دارد، گزینه درس خصوصی را روشن کنید و مدل شهریه، مبلغ و تاریخ شروع را وارد کنید.
3. از **بیشتر > کلاس‌ها** کلاس بسازید: نام، نوع، روزها و ساعت‌ها، مدل شهریه و مبلغ کل.
4. در صفحه کلاس، شاگردان را با تاریخ شروع به کلاس اضافه کنید.
5. از **حضور و غیاب** تاریخ و کلاس را انتخاب کنید، وضعیت‌ها را علامت بزنید و ذخیره کنید.
6. از **مالی** پرداخت‌ها را ثبت کنید و مانده هر شاگرد را ببینید.
7. در پروفایل شاگرد، نمره و یادداشت درس را ثبت کنید.
8. بعد از وارد کردن اطلاعات اولیه، از **تنظیمات** یک پشتیبان JSON بگیرید و یک بار همگام‌سازی کنید.

## همگام‌سازی و تعارض

- داده‌ها اول روی دستگاه ذخیره می‌شوند. با روشن بودن **همگام‌سازی خودکار**، تغییرات چند ثانیه بعد به بک‌اند فرستاده می‌شوند.
- هر حساب معلم یک نسخه شماره‌دار روی سرور دارد. اگر شماره نسخه پایه با سرور نخواند، سرور خطای `SYNC_CONFLICT` برمی‌گرداند و هیچ‌کدام از دو نسخه را عوض نمی‌کند.
- در تعارض، برنامه دو انتخاب می‌دهد:
  - **دریافت از سرور**: نسخه سرور جای نسخه محلی را می‌گیرد.
  - **ارسال نسخه این دستگاه**: نسخه محلی با تأیید شما روی سرور نوشته می‌شود.
- هیچ ادغام خودکاری انجام نمی‌شود. قبل از هر انتخاب، از نسخه‌ای که ممکن است از دست برود پشتیبان بگیرید.
- در اولین اتصال، اگر سرور از قبل داده داشته باشد، بین **استفاده از داده سرور** و **ارسال داده این دستگاه** انتخاب می‌کنید.
- هنگام همگام‌سازی، پرونده شاگردانی که حساب فعال دارند ساخته یا به‌روز می‌شود و رسیدهای جدید خوانده می‌شوند.
- تصویر رسید داخل فایل همگام‌شده نیست؛ فقط هنگام باز کردن رسید از سرور دریافت می‌شود.

## پرونده شاگرد

1. معلم برای شاگرد حساب می‌سازد و نام کاربری و رمز یک‌باره را به او می‌دهد.
2. شاگرد آدرس `https://USERNAME.github.io/REPO/student/` را باز می‌کند و با همان نام کاربری و رمز وارد می‌شود.
3. پرونده شامل اطلاعات همان شاگرد است: وضعیت مالی، حضور و غیاب، نمرات، یادداشت‌های منتشرشده و وضعیت رسیدها. اطلاعات سایر شاگردان در آن نیست.
4. آخرین پرونده در مرورگر شاگرد کش می‌شود و برای مطالعه آفلاین در دسترس است. ارسال رسید و هر نوشتن دیگری به بک‌اند نیاز دارد.
5. اگر حساب شاگرد غیرفعال یا رمزش بازنشانی شود، نشست‌های فعلی بسته می‌شوند.
6. اگر شاگرد بایگانی شود، پرونده او منتشر نمی‌شود.
7. برای انتشار به‌روزرسانی پرونده، معلم باید همگام‌سازی کند. در صفحه شاگرد، کارت **پرونده شاگرد** وضعیت انتشار را نشان می‌دهد.

## رسید پرداخت

1. شاگرد در برنامه شاگرد مبلغ، تاریخ، یادداشت و تصویر رسید را می‌فرستد.
2. تصویر در مرورگر فشرده می‌شود؛ فرمت‌های JPEG، PNG و WebP پذیرفته می‌شوند و سقف هر تصویر ۲ مگابایت است.
3. رسید در بک‌اند ذخیره و برای معلم همان شاگرد قابل دریافت است.
4. معلم با همگام‌سازی، رسیدهای جدید را در **مالی > رسیدهای در انتظار بررسی** می‌بیند.
5. با باز کردن رسید:
   - **تأیید** یک پرداخت جدید با مبلغ و تاریخ قابل ویرایش می‌سازد.
   - **رد** رسید را ردشده علامت می‌زند.
6. اگر پرداخت ساخته‌شده از رسید را حذف کنید، رسید دوباره در انتظار بررسی قرار می‌گیرد.
7. رسیدهای تأییدشده از فهرست انتظار خارج می‌شوند.

## قواعد محاسبه شهریه

### ترم ۱۰ جلسه‌ای

- هر ترم ۱۰ جلسه «حساب‌شده» است.
- شهریه ترم در جلسه‌های ۱، ۱۱، ۲۱ و … اضافه می‌شود.
- جلسه عادی، حتی اگر شاگرد غایب باشد، جزو ۱۰ جلسه حساب می‌شود.
- کنسلی «حساب‌شده» جزو ترم حساب می‌شود و در مدل‌هایی که بر اساس جلسه‌اند هزینه دارد.
- کنسلی «جبرانی» نه جزو ترم است و نه هزینه دارد.
- جلسه جبرانی را در تاریخ واقعی برگزاری‌اش ثبت کنید.

### هر جلسه

- حاضر و با تأخیر هزینه دارند.
- غایب هزینه ندارد.
- کنسلی حساب‌شده هزینه دارد.
- کنسلی جبرانی هزینه ندارد.

### ماهانه

- برای هر ماه شمسی که حداقل یک جلسه عادی یا کنسلی حساب‌شده داشته باشد، یک بار هزینه ثبت می‌شود.
- تعطیلات و کنسلی جبرانی هزینه اضافه ندارند.
- غیبت فردی شاگرد در مدل ماهانه، هزینه را کم نمی‌کند.

### تقسیم شهریه کلاس

- مبلغ کلاس بین شاگردان فعال در تاریخ ثبت هزینه تقسیم می‌شود.
- تقسیم با تعداد شاگردان فعال همان تاریخ انجام و ثابت می‌شود؛ تغییر بعدی تعداد شاگردان، هزینه‌های قبلی را عوض نمی‌کند.
- سهم هر نفر به تومان گرد می‌شود.
- شهریه درس خصوصی ثابت است و بین کسی تقسیم نمی‌شود.
- اگر شهریه کلاس را عوض کنید، مبلغ جدید از تاریخ انتخاب‌شده برای محاسبه‌های بعدی استفاده می‌شود.
- اگر شهریه درس خصوصی را عوض کنید، مبلغ جدید از امروز برای محاسبه‌های بعدی استفاده می‌شود.
- مدل شهریه بعد از ثبت اولین جلسه قفل می‌شود.

### پرداخت و مانده

- پرداخت‌ها برای هر شاگرد جمع می‌شوند.
- مانده = مجموع هزینه‌ها − مجموع پرداخت‌ها.
- مانده مثبت یعنی بدهی، منفی یعنی بستانکاری و صفر یعنی تسویه.
- پرداخت به یک شاگرد خاص تعلق دارد و بین شاگردان تقسیم نمی‌شود.

## حضور و غیاب

- در حالت کلاس، فقط شاگردان فعال در آن تاریخ نمایش داده می‌شوند؛ ثبت‌های قبلی شاگردان خارج‌شده هم برای ویرایش باقی می‌مانند.
- در حالت درس خصوصی، یک شاگرد را انتخاب می‌کنید.
- دکمه **همه حاضر** همه را حاضر می‌کند.
- دکمه **باقی‌مانده‌ها غایب** فقط علامت‌نخورده‌ها را غایب می‌کند.
- تا وقتی همه شاگردان علامت نخورده‌اند، ذخیره انجام نمی‌شود.
- کنسلی جلسه دو حالت دارد: **حساب‌شده** و **جبرانی، بدون هزینه**.
- درصد حضور فقط از جلسه‌های عادی محاسبه می‌شود؛ کنسلی‌ها در درصد اثری ندارند.
- با **لغو کنسلی و ثبت حضور** می‌توانید رکورد کنسلی را حذف کنید و دوباره حضور ثبت کنید.
- حذف کامل جلسه، همه ثبت‌های حضور آن را پاک می‌کند و قابل برگشت نیست.

## بایگانی و حذف

- بایگانی شاگرد یا کلاس، آن را از لیست فعال خارج می‌کند ولی سابقه و بدهی را نگه می‌دارد.
- با بایگانی، عضویت‌های فعال امروز آن شاگرد یا کلاس تمام می‌شوند.
- خروج از بایگانی، عضویت‌های قبلی را خودکار برنمی‌گرداند؛ در صورت نیاز دوباره شاگرد را به کلاس اضافه کنید.
- شاگرد بایگانی‌شده پرونده منتشرشده ندارد و در همگام‌سازی بعدی از فهرست انتشار خارج می‌شود.
- **حذف همه اطلاعات** در تنظیمات، دو تأیید دارد و در مرحله دوم باید کلمه «حذف» را دقیقاً تایپ کنید.
- حذف همه اطلاعات، داده حساب معلم را از این دستگاه و سرور پاک می‌کند، اما حساب کاربری و نشست را حذف نمی‌کند.
- تنظیمات محلی (زبان، تم و رمز قفل) به حالت پیش‌فرض برمی‌گردند. این کار قابل برگشت نیست؛ قبل از آن پشتیبان بگیرید.

## پشتیبان‌گیری و CSV

### پشتیبان JSON در برنامه

- مسیر: **تنظیمات > پشتیبان و خروجی > گرفتن پشتیبان**.
- فایل پشتیبان شامل همه شاگردان، کلاس‌ها، عضویت‌ها، جلسات، حضور، نمرات، پرداخت‌ها، یادداشت‌ها و رسیدهای پرداخت است.
- رمز ورود و نشست‌ها در فایل پشتیبان نیستند.
- بازیابی، همه اطلاعات فعلی را با محتوای فایل عوض می‌کند؛ اما رمز فعلی برنامه حفظ می‌شود.
- قبل از بازیابی، از اطلاعات فعلی پشتیبان بگیرید.
- فایل پشتیبان متن ساده است. آن را در جای امن و ترجیحاً خارج از گوشی نگه دارید.
- پشتیبان JSON جایگزین همگام‌سازی نیست؛ برای انتقال بین دستگاه‌ها یا بازیابی کامل مناسب است.

### پشتیبان روزانه بک‌اند

- `backend/Backup.gs` هر روز یک نسخه کامل در `My Class Backend/_Backups/snapshot-YYYYMMDD-HHmmss` می‌سازد.
- تعداد نسخه‌های نگه‌داری‌شده با `BACKUP_RETENTION` (پیش‌فرض ۱۴) کنترل می‌شود.
- نسخه‌های قدیمی‌تر خودکار حذف می‌شوند.
- برای گرفتن نسخه فوری، تابع `backupCreateSnapshot` را در ویرایشگر Apps Script اجرا کنید.
- برای دیدن وضعیت، `backupStatus` را اجرا کنید.
- برای توقف، `backupRemoveTriggers` را اجرا کنید.
- روش بازیابی و جایگزینی سرور در `backend/README.md` آمده است.

### خروجی CSV

- خروجی حضور و خروجی پرداخت‌ها در تنظیمات موجود است.
- فایل با UTF-8 و BOM ساخته می‌شود تا در Excel فارسی درست باز شود.
- CSV فقط برای مشاهده و تحلیل است؛ برای بازیابی کامل از JSON استفاده کنید.

### خروجی کامل بک‌اند

- اکشن `exportAll` برای مالک برنامه در نظر گرفته شده و با `EXPORT_SECRET` محافظت می‌شود.
- این خروجی شامل فایل‌های داده و تصاویر رسیدهاست و برای مهاجرت یا آرشیو بلندمدت مناسب است.
- آن را فقط در محیط امن و بدون اشتراک‌گذاری عمومی نگه دارید.

## امنیت و حریم خصوصی

- رمزهای بک‌اند با HMAC-SHA256 تکرارشده و نمک اختصاصی هر حساب ذخیره می‌شوند؛ خود رمز ذخیره نمی‌شود.
- نشست معلم و مالک ۷ روز و نشست شاگرد ۳۰ روز اعتبار دارد. سمت سرور فقط هش توکن نشست ذخیره می‌شود.
- بازنشانی رمز یا غیرفعال کردن حساب، همه نشست‌های آن حساب را باطل می‌کند.
- بعد از چند ورود ناموفق، حساب موقتاً قفل می‌شود. پیام‌های ورود عمومی هستند و وجود یا نبود نام کاربری را لو نمی‌دهند.
- شناسه معلم و شاگرد از نشست گرفته می‌شود، نه از بدنه درخواست.
- قواعد دسترسی در بک‌اند اعمال می‌شود: اکشن‌های مدیریتی فقط برای مالک و اکشن‌های حساب شاگرد برای مالک یا معلم صاحب همان شاگرد.
- هیچ رمز، توکن، بدنه درخواست یا محتوای رسید در لاگ نوشته نمی‌شود.
- در مرورگر هیچ Google OAuth، Google Picker، Client ID یا API key وجود ندارد.
- داده‌ها در Drive حساب مالک به‌صورت متن ساده ذخیره می‌شوند و رمزنگاری سرتاسری (E2E) ندارند. امنیت حساب Google مالک و دسترسی Drive او بخش اصلی حفاظت داده‌هاست.
- رمز قفل محلی (PIN) فقط صفحه برنامه را قفل می‌کند و داده IndexedDB را رمزنگاری نمی‌کند.
- رمز حساب معلم یا شاگرد را فقط مالک/معلم صاحب شاگرد می‌تواند بازنشانی کند. بازیابی خودکار رمز وجود ندارد.
- پاک کردن داده‌های مرورگر، حذف برنامه یا حالت ناشناس می‌تواند داده محلی را از بین ببرد. پشتیبان منظم بگیرید.
- پنل مدیریت مالک فقط نام کاربری، نقش، وضعیت، زمان ورود و تعداد حساب‌های شاگرد را نشان می‌دهد؛ داده درسی و مالی معلم‌ها از این پنل در دسترس نیست.
- این برنامه ابزار مالی رسمی نیست و جای دفترکل و نگهداری اسناد رسمی را نمی‌گیرد.

## به‌روزرسانی برنامه

1. قبل از هر به‌روزرسانی، پشتیبان JSON بگیرید.
2. فایل‌های جدید را در همان مخزن GitHub جایگزین کنید؛ پوشه `student/` را هم به‌روز کنید.
3. اگر فایل‌های shell عوض شده‌اند، مقدار `VERSION` در `sw.js` و `student/sw.js` را افزایش دهید.
4. مقدار `APP_VERSION` در `app.js` را هم هماهنگ کنید.
5. تغییرات را push یا آپلود کنید.
6. برنامه را ببندید و دوباره باز کنید. اگر پیام نسخه جدید آمد، همه تب‌های برنامه را ببندید و دوباره باز کنید.
7. بعد از به‌روزرسانی، یک بار آنلاین باز کنید تا فایل‌های جدید ذخیره شوند.

### به‌روزرسانی بک‌اند

1. فایل‌های جدید `backend/Code.gs`، `backend/Backup.gs` و `backend/Export.gs` را در پروژه اصلی جای‌گذاری کنید.
2. در پروژه حساب دوم، `Code.gs`، `BackupMirror.gs` و `Standby.gs` را هماهنگ کنید.
3. در **Deploy > Manage deployments** همان deployment را ویرایش و نسخه جدید را انتخاب کنید.
4. آدرس `/exec` عوض نمی‌شود. اگر عوض شد، `config.js` و نسخه Service Worker را به‌روزرسانی کنید.
5. راه‌اندازی آینه و ارتقای Standby در `backend/README.md` توضیح داده شده است.

## عیب‌یابی

### صفحه ورود می‌گوید سرور تنظیم نشده است

- مقدار `backendUrl` در `config.js` خالی یا اشتباه است.
- آدرس باید به `/exec` ختم شود و بدون `/` انتهایی باشد.
- بعد از تغییر `config.js`، نسخه Service Worker را افزایش دهید و صفحه را با کش‌شکن باز کنید.

### ورود انجام نمی‌شود

- نام کاربری را با حروف کوچک انگلیسی وارد کنید.
- رمز را دقیقاً همان‌طور که دریافت کرده‌اید وارد کنید؛ رمزهای تولیدشده فقط یک بار نمایش داده می‌شوند.
- اگر پیام «تلاش‌های ناموفق زیاد» دیدید، ۱۵ دقیقه صبر کنید.
- اگر حساب شاگرد است، از برنامه `student/` استفاده کنید؛ برنامه معلم حساب شاگرد را نمی‌پذیرد.
- اگر حساب غیرفعال شده است، از مالک یا معلم بخواهید فعالش کند.
- اتصال اینترنت و فعال بودن deployment بک‌اند را بررسی کنید.

### ساخت حساب شاگرد خطای همگام‌سازی می‌دهد

- اول داده‌های معلم را با **همگام‌سازی الان** به سرور بفرستید.
- شاگرد باید در همان داده همگام‌شده وجود داشته باشد و حذف نشده باشد.
- اگر حساب قبلی برای همان شاگرد وجود دارد، از **رمز جدید** استفاده کنید؛ برای هر شاگرد یک حساب مجاز است.

### رمز شاگرد را فراموش کرده‌ام

- معلم در **تنظیمات > حساب‌های شاگرد** دکمه **رمز جدید** را بزند. رمز ۱۲ نویسه‌ای جدید فقط یک بار نشان داده می‌شود.
- مالک برای حساب معلم‌ها در **تنظیمات > حساب‌های معلم** همین کار را انجام می‌دهد.
- رمز قفل محلی (PIN) را می‌توانید از تنظیمات حذف کنید، ولی برای ورود به حساب همچنان نام کاربری و رمز لازم است.

### داده‌ای را نمی‌بینم

- فیلتر فعال/بایگانی را بررسی کنید.
- شاگرد یا کلاس ممکن است بایگانی شده باشد.
- تاریخ حضور و کلاس انتخاب‌شده را بررسی کنید.
- اگر اطلاعات تازه وارد شده‌اند، صفحه را دوباره باز کنید.
- وضعیت آخرین همگام‌سازی و خطای آن را در تنظیمات ببینید.

### همگام‌سازی تعارض می‌دهد

برنامه ادغام خودکار ندارد. یکی از دو نسخه را انتخاب کنید: **دریافت از سرور** یا **ارسال نسخه این دستگاه**. قبل از انتخاب، از نسخه‌ای که ممکن است از دست برود پشتیبان بگیرید. برای جلوگیری از این وضعیت، قبل از شروع کار روی دستگاه دوم همگام‌سازی کنید.

### برنامه آفلاین باز نمی‌شود

- یک بار آنلاین باز کنید تا Service Worker نصب شود.
- مطمئن شوید سایت با HTTPS سرو می‌شود.
- در تنظیمات مرورگر، داده‌های سایت را برای این آدرس بررسی کنید.
- در Chrome از **Install app** استفاده کنید تا تجربه آفلاین پایدارتر باشد.
- صفحه شاگرد Service Worker جداگانه دارد؛ آن را هم یک بار آنلاین باز کنید.

### دکمه نصب نمی‌آید

- در Chrome اندروید و روی HTTPS باز کنید.
- اگر برنامه از قبل نصب شده است، دکمه نصب نمایش داده نمی‌شود.
- از منوی Chrome گزینه **Install app** یا **Add to Home screen** را امتحان کنید.
- در iOS، نصب از طریق Safari و Share انجام می‌شود.

### CSV در Excel به‌هم‌ریخته است

فایل با UTF-8 و BOM ساخته می‌شود. در Excel از **Data > From Text/CSV** استفاده کنید و UTF-8 را انتخاب کنید. برای بازیابی کامل، CSV مناسب نیست؛ از JSON استفاده کنید.

### تاریخ اشتباه است

تاریخ‌ها با تقویم شمسی نمایش داده می‌شوند اما بر اساس تاریخ میلادی ذخیره می‌شوند. تاریخ دستگاه را بررسی کنید. تغییر منطقه زمانی یا ساعت دستگاه می‌تواند «امروز» را جابه‌جا کند.

### شاگرد پرونده را نمی‌بیند

- مطمئن شوید معلم داده‌ها را بعد از آخرین تغییر همگام‌سازی کرده است.
- مطمئن شوید حساب شاگرد فعال است و شاگرد بایگانی نشده است.
- شاگرد باید با همان نام کاربری و رمزی وارد شود که معلم ساخته است.
- اگر رمز بازنشانی شده است، شاگرد باید با رمز جدید وارد شود.

### تصویر رسید ارسال نمی‌شود

- فرمت تصویر باید JPEG، PNG یا WebP باشد.
- تصویر پس از فشرده‌سازی باید کمتر از ۲ مگابایت باشد؛ تصویر کوچک‌تری انتخاب کنید.
- اتصال و فعال بودن حساب شاگرد را بررسی کنید. ارسال رسید در حالت آفلاین انجام نمی‌شود.
- اگر روزانه چند رسید بزرگ می‌فرستید، سهمیه Drive و Apps Script را در نظر بگیرید.

### پشتیبان بک‌اند ساخته نمی‌شود

- توابع `backupCreateSnapshot` و `backupInstallTrigger` را از ویرایشگر Apps Script اجرا کنید و مجوزهای لازم را بدهید.
- وجود پوشه `My Class Backend` و مقدار `ROOT_FOLDER_ID` را بررسی کنید.
- اگر تعداد فایل‌ها از سقف `BACKUP_MAX_FILES` بیشتر شود، اسکریپت خطا می‌دهد؛ پشتیبان JSON در برنامه را جایگزین کنید.

## تست خودکار

این پروژه برای اجرا به npm یا build نیاز ندارد. برای تست‌های Node، Node 18 یا بالاتر کافی است.

```bash
node --test tests/*.test.js
```

بررسی سریع سینتکس همه فایل‌های JavaScript:

```bash
for f in *.js; do node --check "$f" || exit 1; done
node --check student/student.js
```

تست‌ها منطق تاریخ، قالب‌بندی، شهریه، اعتبارسنجی پشتیبان، ساخت پرونده شاگرد، صندوق رسید، ترجمه‌ها، سازگاری فایل‌های shell، نقش‌ها و اسکریپت پشتیبان بک‌اند را بررسی می‌کنند. این تست‌ها جای آزمایش واقعی مرورگر، بک‌اند Apps Script، نصب PWA و لمس صفحه را نمی‌گیرند.
