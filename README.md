# کلاس من

نسخه ۱.۱.۰

برنامه‌ای آفلاین‌محور برای معلم فارسی‌زبان: مدیریت شاگردان، کلاس‌ها، حضور و غیاب، ترم‌های ۱۰ جلسه‌ای، پرداخت‌ها، نمرات و یادداشت‌ها. همه اطلاعات به‌صورت پیش‌فرض روی همان گوشی یا کامپیوتری ذخیره می‌شود که برنامه را باز کرده‌اید. در نسخه ۱.۱.۰ همگام‌سازی اختیاری با Google Drive، پرونده اختصاصی هر شاگرد و بررسی رسید پرداخت اضافه شده است.

## ویژگی‌ها

- طراحی موبایل‌اول با منوی پایین: خانه، شاگردان، حضور و غیاب، مالی، بیشتر.
- رابط کامل فارسی و انگلیسی، راست‌به‌چپ و چپ‌به‌راست، با فونت وزیرمتن.
- تاریخ شمسی برای نمایش و انتخاب تاریخ؛ ذخیره‌سازی داخلی با تاریخ میلادی استاندارد.
- اعداد فارسی و مبلغ به تومان.
- تم روشن، تیره و خودکار.
- قفل برنامه با رمز ۴ تا ۶ رقمی.
- شاگرد خصوصی، نیمه‌خصوصی و گروهی؛ امکان عضویت در چند کلاس و درس خصوصی هم‌زمان.
- کلاس با چند روز و ساعت در هفته.
- سه مدل شهریه: ترم ۱۰ جلسه‌ای، هر جلسه، ماهانه.
- تقسیم خودکار شهریه کلاس بین شاگردان فعال در تاریخ ثبت.
- ثبت حضور، تأخیر، غیبت، کنسلی حساب‌شده و کنسلی جبرانی.
- پرداخت‌ها، بدهی، بستانکاری و تسویه.
- نمرات با نمودار پیشرفت و یادداشت درس.
- یادداشت خصوصی یا قابل نمایش در پرونده شاگرد.
- بایگانی شاگرد و کلاس بدون پاک کردن سابقه.
- همگام‌سازی اختیاری با Google Drive؛ بدون سرور اختصاصی و بدون حساب کاربری برای خود برنامه.
- پرونده اختصاصی هر شاگرد با Google Sign-In و Google Picker.
- ارسال رسید پرداخت توسط شاگرد و بررسی آن در صفحه مالی معلم.
- پشتیبان JSON، بازیابی، خروجی CSV حضور و پرداخت.
- حذف کامل اطلاعات با تأیید دو مرحله‌ای.
- نصب روی اندروید و اجرای آفلاین با Service Worker.
- بدون ارسال داده به سرور برنامه؛ در صورت فعال کردن Drive، فایل‌ها فقط در حساب Google خود معلم و شاگرد ذخیره می‌شوند.

## حریم خصوصی و محدودیت‌ها

- همه داده‌ها در IndexedDB مرورگر روی همان دستگاه ذخیره می‌شوند.
- اگر Google Drive را فعال نکنید، برنامه برای داده‌های خود هیچ تماس شبکه‌ای ندارد.
- Google Drive اختیاری است. با فعال کردن آن، فایل `data.json` در پوشه `Class Manager` حساب Google معلم ساخته می‌شود.
- فایل‌های پرونده شاگرد (`portal.json` و `inbox.json`) در پوشه `student-<شناسه>` داخل همان پوشه ساخته می‌شوند. شاگرد فقط به فایل پرونده خودش دسترسی دارد.
- `portal.json` فقط شامل اطلاعات همان شاگرد است: وضعیت مالی، حضور، نمرات، یادداشت‌های منتشرشده و وضعیت رسیدها. اطلاعات سایر شاگردان و کلاس‌های دیگر در آن نیست.
- `inbox.json` برای ارسال رسید توسط شاگرد قابل نوشتن است؛ شاگرد به `data.json` یا پرونده شاگردان دیگر دسترسی ندارد.
- تصویر رسید در پوشه `proofs` داخل پرونده شاگرد در Drive ذخیره می‌شود. تصویر قبل از ارسال در مرورگر فشرده می‌شود؛ سقف پیش‌فرض هر تصویر ۲ مگابایت است.
- ارتباط با Google روی HTTPS انجام می‌شود، اما داده‌ها با رمزنگاری سرتاسری (E2E) ذخیره نمی‌شوند. Google و سیاست‌های حساب Google در این مسیر دخیل‌اند.
- فایل‌های JSON رمز نمی‌شوند و متن ساده‌اند. پشتیبان و فایل‌های Drive را جای امن نگه دارید.
- رمز ورود فقط صفحه را قفل می‌کند و اطلاعات IndexedDB یا فایل‌های Drive را رمزنگاری نمی‌کند.
- راه بازیابی رمز وجود ندارد. اگر رمز را فراموش کنید، برای ورود دوباره باید داده‌های سایت را پاک کنید؛ در این حالت فقط پشتیبان قبلی نجات‌دهنده است.
- پاک کردن داده‌های مرورگر، حذف برنامه از دستگاه یا استفاده از حالت ناشناس می‌تواند اطلاعات محلی را از بین ببرد. پشتیبان منظم بگیرید.
- همگام‌سازی، ادغام دوطرفه هوشمند ندارد. اگر هم‌زمان روی دو دستگاه تغییر دهید، برنامه برای انتخاب «دریافت از Drive» یا «ارسال این دستگاه» هشدار می‌دهد.
- برای شاگردانی که پرونده فعال دارند، خود شاگرد یا هر کسی که با حساب Google او وارد شود می‌تواند اطلاعات پرونده را ببیند. دسترسی را در صورت نیاز با دکمه «لغو دسترسی شاگرد» قطع کنید.
- لغو دسترسی مانع دسترسی‌های آینده می‌شود، اما نسخه‌ای که در مرورگر شاگرد کش شده است ممکن است تا پاک کردن حافظه مرورگر او باقی بماند.
- حذف یا لغو دسترسی، فایل‌های موجود در Drive را پاک نمی‌کند. برای حذف کامل، فایل‌ها را از Google Drive هم پاک کنید.
- این برنامه ابزار مالی رسمی نیست و جای دفترکل و نگهداری اسناد رسمی را نمی‌گیرد.

## نصب روی GitHub Pages

GitHub Pages یک میزبان رایگان و مناسب برای این برنامه است. برنامه به build یا npm نیاز ندارد.

### ۱. آماده کردن فایل‌ها

همه فایل‌های پوشه برنامه را یک‌جا نگه دارید. فایل `index.html` باید در ریشه همان پوشه‌ای باشد که آدرس سایت را باز می‌کنید. پوشه `student/` هم باید کنار `index.html` قرار بگیرد.

### ۲. ساخت مخزن

1. در GitHub یک مخزن جدید بسازید؛ مثلاً `my-class`.
2. می‌توانید مخزن را Public یا Private بسازید. برای GitHub Pages در پلن رایگان، مخزن Public ساده‌تر است.
3. فایل‌ها را در ریشه مخزن آپلود کنید، نه در یک پوشه تودرتو.

اگر از Git استفاده می‌کنید:

```bash
git init
git add .
git commit -m "Initial release"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
```

جای `USERNAME` و `REPO` را با نام کاربری و نام مخزن خود عوض کنید.

نکته: فایل `.nojekyll` مخفی است. اگر با آپلود دستی GitHub آن را نمی‌بینید، از طریق «Add file > Create new file» یک فایل خالی با نام `.nojekyll` بسازید.

### ۳. فعال کردن Pages

1. در مخزن به **Settings > Pages** بروید.
2. در بخش **Build and deployment** گزینه **Deploy from a branch** را انتخاب کنید.
3. شاخه **main** و پوشه **/(root)** را انتخاب و ذخیره کنید.
4. چند دقیقه صبر کنید تا آدرس سایت آماده شود.

آدرس معمولاً به این شکل است:

```text
https://USERNAME.github.io/REPO/
```

### ۴. نصب روی اندروید

1. آدرس را در Chrome باز کنید.
2. یک بار آنلاین بمانید تا فایل‌ها ذخیره شوند.
3. از منوی Chrome گزینه **Install app** یا **Add to Home screen** را بزنید.
4. بعد از نصب، برنامه را باز کنید و یک بار دیگر آفلاین باز شدن آن را آزمایش کنید.

در iPhone از Safari، دکمه Share و سپس **Add to Home Screen** استفاده کنید. پشتیبانی نصب خودکار در iOS محدودتر است.

### ۵. نکته HTTPS

Service Worker، نصب PWA، Web Crypto، Google Sign-In و Google Picker فقط روی `https://` یا `http://localhost` کار می‌کنند. باز کردن مستقیم `index.html` با `file://` برای استفاده واقعی مناسب نیست.

## اجرای آزمایشی روی کامپیوتر

در پوشه برنامه یک سرور محلی ساده اجرا کنید:

```bash
python3 -m http.server 8000
```

سپس این آدرس را باز کنید:

```text
http://localhost:8000
```

برای بستن سرور، در ترمینال `Ctrl+C` بزنید.

## راه‌اندازی Google Drive

این بخش اختیاری است. بدون آن، همه ویژگی‌های محلی برنامه کار می‌کنند و فقط همگام‌سازی و پرونده شاگرد غیرفعال می‌مانند.

### ۱. ساخت پروژه Google Cloud

1. به [Google Cloud Console](https://console.cloud.google.com/) بروید و یک پروژه بسازید.
2. از **APIs & Services > Library** دو API زیر را فعال کنید:
   - **Google Drive API**
   - **Google Picker API**
3. در **IAM & Admin > Settings** یا صفحه اصلی پروژه، **Project number** را بردارید. این عدد چندرقمی با شناسه پروژه فرق دارد.

### ۲. صفحه رضایت OAuth

1. به **APIs & Services > OAuth consent screen** بروید.
2. نوع کاربر را انتخاب کنید: برای حساب معمولی **External** و برای Google Workspace سازمانی **Internal**.
3. نام برنامه، ایمیل پشتیبانی و ایمیل توسعه‌دهنده را وارد کنید.
4. در بخش scopes این محدوده‌ها را اضافه کنید:
   - `openid`
   - `email`
   - `profile`
   - `https://www.googleapis.com/auth/drive.file`
5. اگر برنامه در حالت **Testing** است، ایمیل Google معلم و شاگردان را در **Test users** اضافه کنید. در غیر این صورت ورود آن‌ها رد می‌شود.
6. برای استفاده واقعی، برنامه را از حالت Testing خارج و منتشر کنید. Google ممکن است برای scopes حساس بررسی انجام دهد؛ این برنامه فقط از `drive.file` استفاده می‌کند که دسترسی محدود به فایل‌های ساخته‌شده یا انتخاب‌شده توسط همان برنامه است.

### ۳. ساخت API key

1. به **APIs & Services > Credentials > Create credentials > API key** بروید.
2. API key را محدود کنید:
   - **API restrictions**: فقط **Google Picker API**.
   - **Application restrictions**: **HTTP referrers**.
   - این آدرس‌ها را اضافه کنید:
     - `https://USERNAME.github.io/*`
     - `http://localhost:8000/*`
     - اگر دامنه اختصاصی دارید، دامنه خودتان را هم اضافه کنید.
3. API key را کپی کنید.

### ۴. ساخت OAuth Client ID

1. در **Credentials > Create credentials > OAuth client ID** نوع **Web application** را انتخاب کنید.
2. در **Authorized JavaScript origins** این آدرس‌ها را اضافه کنید:
   - `https://USERNAME.github.io`
   - `http://localhost:8000`
3. برای این برنامه به Redirect URI نیازی نیست.
4. Client ID را کپی کنید.

### ۵. پر کردن config.js

فایل `config.js` را باز کنید و مقادیر را وارد کنید:

```js
root.APP_CONFIG = {
  googleClientId: '1234567890-abc.apps.googleusercontent.com',
  googleApiKey: 'AIza...',
  googleProjectNumber: '123456789012',
  driveFolderName: 'Class Manager',
  teacherName: 'نام معلم',
  oauthScopes: 'openid email profile https://www.googleapis.com/auth/drive.file',
  maxProofBytes: 2097152
};
```

- `googleClientId` و `googleApiKey` و `googleProjectNumber` هر سه الزامی‌اند.
- `driveFolderName` نام پوشه اصلی در Drive است. پیش‌فرض `Class Manager` است.
- `teacherName` نامی است که در پرونده شاگرد نمایش داده می‌شود. خالی بگذارید تا نام پیش‌فرض استفاده شود.
- `maxProofBytes` سقف حجم تصویر رسید پس از فشرده‌سازی است. مقدار ۲ مگابایت برای اکثر گوشی‌ها مناسب است.
- Client ID و API key در برنامه سمت مرورگر قابل مشاهده‌اند. این طبیعی است؛ امنیت واقعی به محدود کردن API key و scopes OAuth وابسته است. هرگز کلید محرمانه یا Service Account در این فایل قرار ندهید.

### ۶. آزمایش اتصال

1. برنامه را روی HTTPS یا `http://localhost:8000` باز کنید.
2. به **تنظیمات > Google Drive** بروید.
3. **اتصال به Google Drive** را بزنید و با حساب معلم وارد شوید.
4. اگر اجازه دسترسی خواسته شد، به برنامه اجازه دهید.
5. پوشه `Class Manager` و فایل `data.json` ساخته می‌شوند.

اگر پیام «تنظیم نشده» دیدید، یکی از سه مقدار بالا خالی است یا فایل `config.js` بعد از تغییر کش شده است. صفحه را با کش‌شکن باز کنید.

## شروع استفاده

1. در اولین اجرا زبان را انتخاب کنید.
2. یک رمز ۴ تا ۶ رقمی بسازید و تکرار کنید. رمز را جای امن یادداشت کنید.
3. از بخش **شاگردان** شاگرد اضافه کنید. نام الزامی است؛ تلفن، سطح و یادداشت اختیاری‌اند.
4. اگر شاگرد درس خصوصی دارد، گزینه درس خصوصی را روشن کنید و مدل شهریه، مبلغ و تاریخ شروع را وارد کنید.
5. از بخش **بیشتر > کلاس‌ها** کلاس بسازید: نام، نوع، روزها و ساعت‌ها، مدل شهریه و مبلغ کل.
6. در صفحه کلاس، شاگردان را با تاریخ شروع به کلاس اضافه کنید.
7. از **حضور و غیاب** تاریخ و کلاس را انتخاب کنید، وضعیت‌ها را علامت بزنید و ذخیره کنید.
8. از **مالی** پرداخت‌ها را ثبت کنید و مانده هر شاگرد را ببینید.
9. در پروفایل شاگرد، نمره و یادداشت درس را ثبت کنید.
10. بعد از وارد کردن اطلاعات اولیه، از **تنظیمات** یک پشتیبان JSON بگیرید.

## همگام‌سازی Google Drive

همگام‌سازی روی فایل `data.json` در پوشه Drive کار می‌کند و کل داده‌های معلم را شامل می‌شود.

### اتصال اولیه

- به **تنظیمات > Google Drive** بروید و **اتصال** را بزنید.
- اگر `data.json` وجود نداشته باشد، داده‌های محلی به Drive فرستاده می‌شوند.
- اگر `data.json` از قبل وجود داشته باشد، برنامه دو گزینه می‌دهد:
  - **دریافت از Drive**: داده‌های محلی با نسخه Drive جایگزین می‌شوند.
  - **ارسال نسخه این دستگاه**: نسخه محلی روی `data.json` نوشته می‌شود.
- این انتخاب همگام‌سازی ادغامی نیست. قبل از انتخاب، از نسخه‌ای که می‌خواهید نگه دارید پشتیبان بگیرید.

### همگام‌سازی خودکار

- بعد از هر تغییر محلی، اگر همگام‌سازی خودکار روشن باشد، حدود ۶ ثانیه بعد ارسال انجام می‌شود.
- همگام‌سازی خودکار فقط وقتی کار می‌کند که برنامه به Drive متصل باشد و توکن ورود Google معتبر باشد.
- بعد از قفل شدن برنامه، تازه‌سازی صفحه یا باز شدن مجدد، توکن Google در حافظه پاک می‌شود. برای اولین همگام‌سازی دوباره، **همگام‌سازی الان** را بزنید یا دوباره وارد Google شوید.
- **همگام‌سازی الان** در حالت بدون تغییر، صندوق رسیدهای شاگردان را هم می‌خواند.
- اگر رسید جدیدی پیدا شود، تصویر آن در پوشه `proofs` ذخیره و در صفحه مالی نمایش داده می‌شود.

### تعارض

- اگر `data.json` روی Drive از دستگاه دیگر تغییر کرده باشد، برنامه هشدار تعارض می‌دهد.
- گزینه **دریافت از Drive** نسخه Drive را جایگزین می‌کند.
- گزینه **ارسال این دستگاه** نسخه محلی را با تأیید شما جایگزین می‌کند.
- هیچ ادغام خودکاری بین دو نسخه انجام نمی‌شود. برای کار چنددستگاهی، همیشه قبل از تغییر روی دستگاه دیگر، همگام‌سازی کنید.

### قطع اتصال

- **قطع اتصال** توکن Google را لغو می‌کند و همگام‌سازی خودکار را متوقف می‌کند.
- داده‌های محلی و فایل‌های Drive پاک نمی‌شوند.
- با اتصال دوباره می‌توانید دوباره همان پوشه و `data.json` را انتخاب کنید.

### فایل‌های Drive

```text
Class Manager/
  data.json                  کل داده‌های معلم؛ فقط حساب معلم
  student-<ID>/
    portal.json              اطلاعات فیلترشده همان شاگرد؛ خواندنی
    inbox.json               صندوق رسیدهای همان شاگرد؛ قابل نوشتن
    proofs/
      proof-<ID>.jpg         تصویر رسید فشرده‌شده
```

- `data.json` هیچ‌وقت با شاگرد به اشتراک گذاشته نمی‌شود.
- `portal.json` با نقش **Reader** و `inbox.json` با نقش **Writer** با ایمیل Google شاگرد به اشتراک گذاشته می‌شوند.
- اگر ایمیل شاگرد عوض شود، دسترسی قبلی هنگام انتشار بعدی برداشته می‌شود.
- Google Drive ممکن است فایل‌ها را با نام و ساختار مشابه نشان دهد؛ نام پوشه را تغییر ندهید.

## پرونده شاگرد

پرونده شاگرد به شاگرد اجازه می‌دهد وضعیت خودش را ببیند و رسید پرداخت بفرستد، بدون اینکه به داده کامل معلم دسترسی داشته باشد.

### فعال‌سازی توسط معلم

1. شاگرد را باز یا ویرایش کنید.
2. **ایمیل Google شاگرد** را وارد کنید.
3. گزینه **پرونده شاگرد فعال باشد** را روشن کنید.
4. ذخیره کنید.
5. در صفحه شاگرد، کارت **پرونده شاگرد** را ببینید:
   - اگر Drive متصل نیست، **اتصال** را بزنید.
   - **انتشار این پرونده** را بزنید.
   - بعد از انتشار، وضعیت **فعال** می‌شود.
6. از همان کارت می‌توانید **برنامه شاگرد** را باز کنید یا لینک آن را کپی کنید.
7. برای انتشار گروهی، در **تنظیمات > Google Drive** دکمه **انتشار پرونده شاگردان** را بزنید. این دکمه همه شاگردان فعال با ایمیل را منتشر و شاگردان غیرفعال یا بایگانی‌شده را لغو می‌کند.

### استفاده توسط شاگرد

1. لینک برنامه شاگرد را باز کنید: `https://USERNAME.github.io/REPO/student/`
2. با همان ایمیل Google وارد شوید.
3. یک بار فایل‌های `portal.json` و `inbox.json` خود را با Google Picker انتخاب کنید.
4. از این به بعد اطلاعات در حافظه مرورگر شاگرد کش می‌شود و آفلاین هم قابل مشاهده است.
5. بخش‌های قابل مشاهده:
   - وضعیت مالی، بدهی/بستانکاری، هزینه‌ها و پرداخت‌ها
   - حضور و غیاب و درصد حضور
   - نمرات
   - یادداشت‌های منتشرشده
   - وضعیت رسیدهای ارسالی
6. شاگرد می‌تواند رسید جدید بفرستد. اگر آفلاین باشد، رسید در صف محلی می‌ماند و بعداً ارسال می‌شود.

### نکات مهم پرونده

- شاگرد باید همان ایمیلی را وارد کند که معلم در پرونده ثبت کرده است.
- اگر فایل‌ها را جابه‌جا یا حذف کنید، شاگرد باید دوباره با Picker انتخاب کند.
- شاگرد می‌تواند فایل `portal.json` را ببیند؛ پس اطلاعات حساسی را در یادداشت عمومی یا فیلدهای پرونده قرار ندهید.
- برای بستن دسترسی، در کارت پرونده **لغو دسترسی شاگرد** را بزنید. فایل‌ها در Drive باقی می‌مانند.
- اگر پرونده فعال نباشد یا ایمیل ثبت نشده باشد، کارت پرونده راهنمای رفع مشکل نشان می‌دهد.

## رسید پرداخت

1. شاگرد در برنامه شاگرد، مبلغ، تاریخ، یادداشت و تصویر رسید را می‌فرستد.
2. تصویر در مرورگر به JPEG فشرده و حداکثر تا `maxProofBytes` کوچک می‌شود.
3. رسید در `inbox.json` شاگرد قرار می‌گیرد.
4. معلم با **همگام‌سازی الان** یا همگام‌سازی خودکار، رسیدها را می‌خواند.
5. در **مالی**، بخش **رسیدهای در انتظار بررسی** نمایش داده می‌شود.
6. با باز کردن رسید:
   - تصویر در صورت امکان پیش‌نمایش داده می‌شود.
   - **تأیید** یک پرداخت جدید با مبلغ و تاریخ قابل ویرایش می‌سازد.
   - **رد** رسید را رد‌شده علامت می‌زند.
7. پرداخت تأییدشده در پرونده شاگرد و وضعیت مالی نمایش داده می‌شود.

نکته: اگر پرداخت ساخته‌شده از رسید را حذف کنید، رسید دوباره به وضعیت «در انتظار بررسی» برمی‌گردد تا سابقه ناسازگار نماند.

## قواعد محاسبه شهریه

### ترم ۱۰ جلسه‌ای

- هر ترم ۱۰ جلسه «حساب‌شده» است.
- شهریه ترم در جلسه‌های ۱، ۱۱، ۲۱ و … اضافه می‌شود.
- جلسه عادی، حتی اگر شاگرد غایب باشد، جزو ۱۰ جلسه حساب می‌شود.
- کنسلی «حساب‌شده» جزو ترم حساب می‌شود و در مدل‌هایی که بر اساس جلسه‌اند هزینه دارد.
- کنسلی «جبرانی» نه جزو ترم است و نه هزینه دارد.
- جلسه جبرانی را در تاریخ واقعی برگزاری‌اش ثبت کنید.

### هر جلسه

- حاضر و با تأخیر هزینه دارند.
- غایب هزینه ندارد.
- کنسلی حساب‌شده هزینه دارد.
- کنسلی جبرانی هزینه ندارد.

### ماهانه

- برای هر ماه شمسی که حداقل یک جلسه عادی یا کنسلی حساب‌شده داشته باشد، یک بار هزینه ثبت می‌شود.
- تعطیلات و کنسلی جبرانی هزینه اضافه ندارند.
- غیبت فردی شاگرد در مدل ماهانه، هزینه را کم نمی‌کند.

### تقسیم شهریه کلاس

- مبلغ کلاس بین شاگردان فعال در تاریخ ثبت هزینه تقسیم می‌شود.
- تقسیم با تعداد شاگردان فعال همان تاریخ انجام و ثابت می‌شود؛ تغییر بعدی تعداد شاگردان، هزینه‌های قبلی را عوض نمی‌کند.
- سهم هر نفر به تومان گرد می‌شود.
- شهریه درس خصوصی ثابت است و بین کسی تقسیم نمی‌شود.
- اگر شهریه کلاس را عوض کنید، مبلغ جدید از تاریخ انتخاب‌شده برای محاسبه‌های بعدی استفاده می‌شود.
- اگر شهریه درس خصوصی را عوض کنید، مبلغ جدید از امروز برای محاسبه‌های بعدی استفاده می‌شود.
- مدل شهریه بعد از ثبت اولین جلسه قفل می‌شود.

### پرداخت و مانده

- پرداخت‌ها برای هر شاگرد جمع می‌شوند.
- مانده = مجموع هزینه‌ها − مجموع پرداخت‌ها.
- مانده مثبت یعنی بدهی، منفی یعنی بستانکاری و صفر یعنی تسویه.
- پرداخت به یک شاگرد خاص تعلق دارد و بین شاگردان تقسیم نمی‌شود.

## حضور و غیاب

- در حالت کلاس، فقط شاگردان فعال در آن تاریخ نمایش داده می‌شوند؛ ثبت‌های قبلی شاگردان خارج‌شده هم برای ویرایش باقی می‌مانند.
- در حالت درس خصوصی، یک شاگرد را انتخاب می‌کنید.
- دکمه **همه حاضر** همه را حاضر می‌کند.
- دکمه **باقی‌مانده‌ها غایب** فقط علامت‌نخورده‌ها را غایب می‌کند.
- تا وقتی همه شاگردان علامت نخورده‌اند، ذخیره انجام نمی‌شود.
- کنسلی جلسه دو حالت دارد: **حساب‌شده** و **جبرانی، بدون هزینه**.
- درصد حضور فقط از جلسه‌های عادی محاسبه می‌شود؛ کنسلی‌ها در درصد اثری ندارند.
- با **لغو کنسلی و ثبت حضور** می‌توانید رکورد کنسلی را حذف کنید و دوباره حضور ثبت کنید.
- حذف کامل جلسه، همه ثبت‌های حضور آن را پاک می‌کند و قابل برگشت نیست.

## بایگانی و حذف

- بایگانی شاگرد یا کلاس، آن را از لیست فعال خارج می‌کند ولی سابقه و بدهی را نگه می‌دارد.
- با بایگانی، عضویت‌های فعال امروز آن شاگرد یا کلاس تمام می‌شوند.
- خروج از بایگانی، عضویت‌های قبلی را خودکار برنمی‌گرداند؛ در صورت نیاز دوباره شاگرد را به کلاس اضافه کنید.
- بایگانی شاگرد، در همگام‌سازی بعدی دسترسی پرونده او را لغو می‌کند.
- **حذف همه اطلاعات** در تنظیمات، دو تأیید دارد و در مرحله دوم باید کلمه «حذف» را دقیقاً تایپ کنید.
- حذف همه اطلاعات، رمز، تنظیمات و وضعیت اتصال Drive را از حافظه برنامه پاک می‌کند و برنامه به صفحه راه‌اندازی اولیه برمی‌گردد. فایل‌های Drive با این کار پاک نمی‌شوند.
- این کار قابل برگشت نیست. قبل از آن پشتیبان بگیرید.

## پشتیبان‌گیری و CSV

### پشتیبان JSON

- مسیر: **تنظیمات > پشتیبان‌گیری > گرفتن پشتیبان**.
- فایل پشتیبان شامل همه شاگردان، کلاس‌ها، عضویت‌ها، جلسات، حضور، نمرات، پرداخت‌ها، یادداشت‌ها و رسیدهای پرداخت است.
- رمز ورود در فایل پشتیبان ذخیره نمی‌شود.
- بازیابی، همه اطلاعات فعلی را با محتوای فایل عوض می‌کند؛ اما رمز فعلی برنامه حفظ می‌شود.
- قبل از بازیابی، از اطلاعات فعلی پشتیبان بگیرید.
- فایل پشتیبان متن ساده است. آن را در جای امن و ترجیحاً خارج از گوشی نگه دارید.
- پشتیبان JSON جایگزین همگام‌سازی Drive نیست؛ برای انتقال بین دستگاه‌ها یا بازیابی کامل مناسب است.

### CSV

- خروجی حضور و خروجی پرداخت‌ها در تنظیمات موجود است.
- فایل با UTF-8 و BOM ساخته می‌شود تا در Excel فارسی درست باز شود.
- CSV فقط برای مشاهده و تحلیل است؛ برای بازیابی کامل از JSON استفاده کنید.

## امنیت و رمز ورود

- رمز ۴ تا ۶ رقمی است و با PBKDF2 و نمک تصادفی ذخیره می‌شود؛ خود رمز ذخیره نمی‌شود.
- بعد از پنج تلاش اشتباه، ورود ۳۰ ثانیه قفل می‌شود.
- رمز فقط قفل صفحه است، نه رمزنگاری داده‌ها.
- راه بازیابی رمز وجود ندارد.
- برای تغییر رمز: **تنظیمات > امنیت > تغییر رمز**.
- برای قفل فوری: دکمه قفل در سربرگ یا **تنظیمات > قفل برنامه**.
- توکن Google Drive فقط در حافظه نگه داشته می‌شود و با قفل کردن برنامه یا بستن صفحه پاک می‌شود.
- برای قطع دسترسی برنامه از سمت Google، به [حساب Google > امنیت > دسترسی‌های شخص ثالث](https://myaccount.google.com/permissions) بروید و دسترسی برنامه را حذف کنید.
- برای شاگردان، لغو دسترسی از کارت پرونده شاگرد یا حذف دسترسی فایل در Drive انجام می‌شود.

## به‌روزرسانی برنامه

1. قبل از هر به‌روزرسانی، پشتیبان JSON بگیرید.
2. فایل‌های جدید را در همان مخزن GitHub جایگزین کنید؛ پوشه `student/` را هم به‌روز کنید.
3. اگر فایل‌های برنامه عوض شده‌اند، مقدار `VERSION` در `sw.js` و در صورت نیاز `student/sw.js` را افزایش دهید؛ مثلاً از `my-class-v1.1.0` به `my-class-v1.1.1`.
4. مقدار `APP_VERSION` در `app.js` را هم هماهنگ کنید.
5. تغییرات را push یا آپلود کنید.
6. برنامه را ببندید و دوباره باز کنید. اگر پیام نسخه جدید آمد، همه تب‌های برنامه را ببندید و دوباره باز کنید.
7. بعد از به‌روزرسانی، یک بار آنلاین باز کنید تا فایل‌های جدید ذخیره شوند.

نسخه نمایش‌داده‌شده در برنامه در فایل `app.js` با `APP_VERSION` تنظیم می‌شود.

## عیب‌یابی

### صفحه سفید یا خالی است

- آدرس را با `https://` یا `http://localhost` باز کنید، نه `file://`.
- کنسول مرورگر را باز کنید و خطاهای JavaScript را ببینید.
- مطمئن شوید `index.html` در ریشه آدرس است و فایل‌های CSS و JS کنار آن هستند.
- اگر تازه آپلود کرده‌اید، چند دقیقه صبر کنید و کش مرورگر را خالی کنید.

### خطای حافظه یا باز نشدن IndexedDB

- از Chrome به‌روز استفاده کنید.
- برنامه را روی HTTPS باز کنید.
- حالت ناشناس یا محدودیت ذخیره‌سازی مرورگر را بررسی کنید.
- اگر داده قبلی ندارید، داده‌های سایت را پاک کنید و دوباره راه‌اندازی کنید.

### رمز را فراموش کرده‌ام

راه بازیابی وجود ندارد. اگر پشتیبان دارید، داده‌های سایت را پاک کنید، برنامه را دوباره راه‌اندازی کنید و پشتیبان را بازیابی کنید. رمز جدید را در راه‌اندازی اولیه بسازید. بدون پشتیبان، داده‌های داخل برنامه قابل بازیابی نیستند.

### داده‌ای را نمی‌بینم

- فیلتر فعال/بایگانی را بررسی کنید.
- شاگرد یا کلاس ممکن است بایگانی شده باشد.
- تاریخ حضور و کلاس انتخاب‌شده را بررسی کنید.
- اگر اطلاعات تازه وارد شده‌اند، صفحه را دوباره باز کنید.
- اگر همگام‌سازی فعال است، وضعیت اتصال و آخرین خطا را در تنظیمات ببینید.

### برنامه آفلاین باز نمی‌شود

- یک بار آنلاین باز کنید تا Service Worker نصب شود.
- مطمئن شوید سایت با HTTPS سرو می‌شود.
- در تنظیمات مرورگر، داده‌های سایت را برای این آدرس بررسی کنید.
- در Chrome از **Install app** استفاده کنید تا تجربه آفلاین پایدارتر باشد.
- صفحه شاگرد Service Worker جداگانه دارد؛ آن را هم یک بار آنلاین باز کنید.

### دکمه نصب نمی‌آید

- در Chrome اندروید و روی HTTPS باز کنید.
- اگر برنامه از قبل نصب شده است، دکمه نصب نمایش داده نمی‌شود.
- از منوی Chrome گزینه **Install app** یا **Add to Home screen** را امتحان کنید.
- در iOS، نصب از طریق Safari و Share انجام می‌شود.

### CSV در Excel به‌هم‌ریخته است

فایل با UTF-8 و BOM ساخته می‌شود. در Excel از **Data > From Text/CSV** استفاده کنید و UTF-8 را انتخاب کنید. برای بازیابی کامل، CSV مناسب نیست؛ از JSON استفاده کنید.

### تاریخ اشتباه است

تاریخ‌ها با تقویم شمسی نمایش داده می‌شوند اما بر اساس تاریخ میلادی ذخیره می‌شوند. تاریخ دستگاه را بررسی کنید. تغییر منطقه زمانی یا ساعت دستگاه می‌تواند «امروز» را جابه‌جا کند.

### Google Drive وصل نمی‌شود

- وجود هر سه مقدار `googleClientId`، `googleApiKey` و `googleProjectNumber` را در `config.js` بررسی کنید.
- آدرس دقیق سایت را در **Authorized JavaScript origins** و **HTTP referrers** اضافه کنید؛ آدرس باید بدون مسیر و بدون `/` انتهایی باشد (مثلاً `https://USERNAME.github.io`).
- Google Drive API و Google Picker API را فعال کنید.
- اگر OAuth در حالت Testing است، ایمیل معلم و شاگرد را در Test users اضافه کنید.
- از حالت ناشناس، مسدودکننده تبلیغات یا مسدودکننده کوکی شخص ثالث استفاده نکنید؛ ورود Google به پنجره و کوکی نیاز دارد.
- اگر پس از قفل یا بستن برنامه خطای احراز هویت دیدید، **همگام‌سازی الان** را بزنید و دوباره وارد Google شوید.
- خطای ۴۰۳ یا «دسترسی ندارید» معمولاً یعنی فایل با ایمیل دیگری به اشتراک گذاشته شده یا دسترسی آن لغو شده است.

### شاگرد فایل‌های پرونده را نمی‌بیند

- معلم باید ایمیل Google شاگرد را دقیقاً ثبت و پرونده را فعال کرده باشد.
- پرونده باید منتشر شده باشد و وضعیت آن در کارت شاگرد «فعال» باشد.
- شاگرد باید با همان ایمیل وارد شود.
- در Google Picker، فایل‌های `portal.json` و `inbox.json` خودش را انتخاب کند.
- اگر فایل‌ها جابه‌جا شده‌اند، دوباره انتخاب کند.
- اگر دسترسی لغو شده است، معلم باید دوباره انتشار کند.

### تصویر رسید ارسال نمی‌شود

- فرمت تصویر باید JPEG، PNG یا WebP باشد.
- تصویر پس از فشرده‌سازی باید از `maxProofBytes` کوچک‌تر باشد. مقدار را در `config.js` افزایش دهید یا تصویر کوچک‌تری انتخاب کنید.
- شاگرد باید به `inbox.json` دسترسی Writer داشته باشد.
- اگر آفلاین است، رسید در صف می‌ماند؛ بعد از اتصال دوباره تلاش کنید.
- اگر `inbox.json` توسط فایل دیگری تغییر کرده باشد، برنامه یک بار دیگر تلاش می‌کند؛ در صورت تکرار، صفحه شاگرد را دوباره باز کنید.

### تغییرات بین دو دستگاه قاطی شده‌اند

برنامه ادغام خودکار ندارد. یکی از دو نسخه را انتخاب کنید: **دریافت از Drive** یا **ارسال این دستگاه**. قبل از انتخاب، از نسخه‌ای که ممکن است از دست برود پشتیبان بگیرید. برای جلوگیری از این وضعیت، قبل از شروع کار روی دستگاه دوم، همگام‌سازی کنید.

## تست خودکار

این پروژه برای اجرا به npm یا build نیاز ندارد. برای تست‌های Node، Node 18 یا بالاتر کافی است.

```bash
node --test tests/*.test.js
```

بررسی سریع سینتکس همه فایل‌های JavaScript:

```bash
for f in *.js; do node --check "$f" || exit 1; done
node --check student/student.js
```

تست‌های خودکار منطق تاریخ، قالب‌بندی، شهریه، اعتبارسنجی پشتیبان، ساخت داده پرونده شاگرد، اعتبارسنجی صندوق رسید، ترجمه‌ها و سازگاری فایل‌ها را بررسی می‌کنند. این تست‌ها جای آزمایش واقعی مرورگر، Google Drive، نصب PWA و لمس صفحه را نمی‌گیرند.
